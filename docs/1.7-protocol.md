# VEE 1.7 server protocol (WP-P) — as implemented on `feature/1.7-server`

Contract for the UI lane. Everything below is pinned by tests
(`InlineIntentTest`, `InlineDuplicateTest`, `InlineRestoreTest`,
`InlineCascadeTest`, `InlineSecurityRegressionTest`, `inline-record-actions.test.js`).

COMMON intent keys (unchanged): `action`, `parentTable`, `parentUid`, `field`, `revision`.
Any other key → HTTP 400 before a record is read.

## Intents

| action | extra keys | client builder |
|---|---|---|
| `duplicate` | `childUid` (required, int > 0): the `uid` of a listed entry (not `state: 'deleted'`) | `collectionIntent(field, 'duplicate', {childUid})` |
| `restore` | `childUid` (required, int > 0): the `uid` shown on a `state: 'deleted'` row (= its live uid) | `collectionIntent(field, 'restore', {childUid})` |

### duplicate — response 200

```json
{"success": true, "uid": 17,
 "created": {"uid": 17, "table": "tx_vee_item", "hidden": true, "hiddenField": "hidden"},
 "duplicated": {"uid": 1},
 "workspace": {"id": 0, "firstVersion": false},
 "collections": [/* public fields */]}
```

`created.hidden` is what Core stored (createHidden in live → true; workspace → source visibility).

Refusals (409 unless noted, `{success:false, reason, collection}`):
`copyUnsupported` (entry has nested inline/file members; any entry below a connected
translated parent), `max`, `controls` (`enabledControls.new = false`,
`showNewRecordLink = false`, page TSconfig `inlineRecords.duplicate = 0`), `stale`
(childUid not a listed live/draft entry, or revision changed), and the collection /
add reasons: `rights`, `language`, `hidden`, `firstVersion`, `workspace`,
`translation`, `synchronized`, `unsupported`, `disabled`, `busy`; `deleted` on placeholders.

### restore — response 200

```json
{"success": true, "uid": null,
 "restored": {"uid": 3, "translations": 1},
 "workspace": {"id": 1, "firstVersion": false},
 "collections": [/* public fields */]}
```

Refusals: `restoreLive` (not in a workspace; checked first), `stale` (no delete
placeholder listed under that uid — a version uid or a normal entry's uid is stale too),
`rights`, `max`, collection reasons `unsupported`, `disabled`, `workspace`, `busy`.

## Payload additions

Per child (every listed entry, placeholders included):

| key | values |
|---|---|
| `canDuplicate`, `duplicateReason` | `''` or a reason above; `'deleted'` on placeholders |
| `cascade` | `{translations, languages, children, files, truncated}` — `children` = nested records (incl. their translations), `files` = `sys_file_reference` rows (files stay), `truncated` = walk stopped at a bound |
| `cascadeReason` | `''`, or when `deleteReason === 'cascade'`: `depth` \| `records` \| `rights` \| `disabled` |

Per delete placeholder (`state: 'deleted'`) only:

| key | values |
|---|---|
| `canRestore`, `restoreReason` | `''`, `rights`, `max`, `unsupported`, `disabled`, `workspace` |

Delete response `deleted` gains `children`, `files`: `{uid, verb, translations, children, files}`.

## Labels (XLF EN + DE, `frontend.inlineRecords.<key>`)

`copyUnsupported`, `restoreLive`, `cascadeDepth`, `cascadeRecords`, `cascadeRights`,
`cascadeDisabled`. A cascade refusal: show `cascade` + capitalised `cascadeReason`
(`cascadeRecords`), falling back to `cascade`. Buttons/confirm texts ("Duplicate",
"Undo removal", "Also removes N nested entries and M file references") are the UI lane's.

## Page TSconfig (`tx_visualeditorenhancements.inlineRecords.`)

`firstVersion = 1` (default flipped), `duplicate = 1`, `cascade.enabled = 1`,
`cascade.maxDepth = 3`, `cascade.maxRecords = 50`.

## Deviations from the brief / plan (and why)

1. **duplicate uses `copy` with `{target: -uid, ignoreLocalization: true}`**, not the
   paste envelope `{action: 'paste', target, update}`: Core's paste branch cannot carry
   `ignoreLocalization`, and without it Core copies the source's translations into the
   translated parents' relations (writes outside the collection lock, translated
   parent counts not updated). The `hidden = 1` update runs in the follow-up datamap
   together with the parent list. Consequence: a copy has no translations yet
   (`untranslated` lists the languages; *Sync translations* adds them).
2. **duplicate response** also carries `created.table` (parity with create) and
   `duplicated {uid}`.
3. **restore** additionally runs Core `version` (`{action: 'new'}`) on a *leaf* entry
   (and on leaf translation entries) whose owner has a draft in this workspace. Without
   it the discarded entry is live-only below a drafted parent, and every later add/move/
   remove would be refused `workspace` (1.6 rule). Entries with live nested members are
   not re-drafted (Core would version the members with live bookkeeping); for them the
   collection reports `workspace` afterwards, exactly as after a discard in the
   Workspaces module. Strict live snapshot (no first-version mask) guards both commands.
4. **restore also discards translation placeholders** of the entry (Core's discard looks
   translations up by the version uid and would leave them).
5. **`cascade.enabled`** is the switch behind `cascadeReason: 'disabled'` (the brief named
   the reason, not the key).
6. **`canRestore`/`restoreReason` exist on placeholder rows only**; normal rows have no
   such keys.
7. Restore discards the entry's whole draft (Core): earlier unpublished changes of that
   entry in the workspace are gone. Documented in Collections.rst.
